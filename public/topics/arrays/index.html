Arrays · sorting · searching

Array and sorting visualiser in 3D

An array is a run of neighbouring slots, and almost every off-by-one bug in a loop over one comes from losing track of an index. Algo3D draws the array as a row of 3D tiles, keeps i, j, min, lo, hi and mid on screen as they move, and pauses on every comparison, so you can see the exact step where the order changes.

Open the array view and step through a live sort, or paste your own program.

What the 3D view shows

  • Every slot is a tile with its value on top and its index underneath, so a[3] is a place you can point at.
  • Pointer chips ride above the tile they name, so i and j are never a mental arithmetic exercise.
  • The pair being compared lifts in gold, a swap moves both tiles through the air in rose, and the sorted tail settles in sage.
  • A note under the scene says what just happened in words — “compare a[2] = 9 with a[3] = 1” — beside the matching line of code.
  • Drag to orbit, scroll to zoom, click any tile to inspect its index and value.

Algorithms in the library

AlgorithmWhat it doesTime
Bubble sortCompares neighbours and swaps them until a pass makes no changeO(n²), O(n) on an already sorted array
Selection sortFinds the minimum of the unsorted tail and moves it to the frontO(n²) always
Insertion sortLifts each key and shifts the larger values right to make roomO(n²), O(n) nearly sorted
Linear searchChecks every slot from the startO(n)
Binary searchHalves the range with lo, hi and midO(log n), sorted input

The code that runs

The library programs are Java, traced line by line by the interpreter in the browser. This is bubble sort, early-exit included: 

void bubbleSort(int[] a) {
    int n = a.length;
    for (int i = 0; i < n - 1; i++) {
        boolean swapped = false;
        for (int j = 0; j < n - 1 - i; j++) {
            if (a[j] > a[j + 1]) {
                int tmp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = tmp;
                swapped = true;
            }
        }
        if (!swapped) break;   // nothing moved: the array is sorted
    }
}

The same view also traces selectionSort, insertionSort, linearSearch and binarySearch, and each one keeps its own index pointers on the scene as the loop turns.

Why an array view is worth the screen

Sorting is the first place a beginner meets a nested loop, and a nested loop is the first place “which index is which” stops being obvious. Watching j run up to n - 1 - i, then seeing the range of the inner loop shrink by one after each pass, is the difference between memorising a bound and understanding it.

Binary search is the other one: the array doesn’t move at all, only the window does. Seeing lo and hi close in on a value makes the halving obvious, and makes the “why does this need a sorted array” question answer itself.
