Trees · recursion · balanced search

Binary search tree visualiser in 3D

A binary search tree is a recursive rule made of nodes: everything smaller goes left, everything larger goes right, and the same rule holds in every subtree. Algo3D draws the tree in space, lights the comparison path during an insert, and recurses visibly during an in-order traversal.

What the 3D view shows

  • One block per node, placed by depth, with edges to its left and right child.
  • An insert starts at the root and moves down one comparison at a time, with the visited nodes highlighted on the way.
  • A missing child is where the new node appears — the search for a place and the insert are the same walk.
  • In-order traversal visits left subtree, node, right subtree, and the scene shows the visit order as values leave the tree.
  • Search stops on a hit or on a null, which is the difference between “not found” and “still going”.

The cost of each operation

OperationWhat happensTime
InsertOne comparison per level, then attach a leafO(log n) balanced, O(n) degenerate
SearchSame walk, stopping on a hit or a null childO(log n) balanced, O(n) degenerate
In-order traversalEvery node exactly onceO(n)
Minimum / maximumFollow left or right to the endO(log n) balanced

The second half of every row is the honest half. Insert already-sorted values and the tree becomes a linked list with extra steps; the shape in the scene is the explanation.

The code that runs

class Node {
    int value;
    Node left, right;
}

Node insert(Node node, int value) {
    if (node == null) return new Node(value);   // found the empty slot
    if (value < node.value) node.left = insert(node.left, value);
    else if (value > node.value) node.right = insert(node.right, value);
    return node;                                // duplicates are ignored
}

void inorder(Node node, List<Integer> out) {
    if (node == null) return;
    inorder(node.left, out);                    // everything smaller
    out.add(node.value);                        // visit
    inorder(node.right, out);                   // everything larger
}

Why the tree is worth drawing

Recursion is usually taught with a call stack diagram, which explains the mechanism but not the shape. A tree drawn in space shows both at once: the recursion is the descent, and the in-order output is the sorted order, which is the reason the structure exists.

The degenerate case is the other reason. Seven ascending values produce a chain, and seeing that chain next to a balanced tree makes “a BST is only fast if it is balanced” something you have looked at rather than something you have been told.
