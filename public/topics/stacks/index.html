Stacks · LIFO · push and pop

Stack visualiser in 3D

A stack has one end that matters. Algo3D shows that literally: the array is a tower of plates, and push, pop and peek only ever touch the plate on top. The last value in is the first value out, and the scene never lets you forget it.

What the 3D view shows

  • Each value is a plate in a vertical tower, with its slot index printed beside it.
  • A push drops a new plate onto the top; a pop lifts the top plate away, and everything below it stays exactly where it was.
  • The top plate is highlighted, because that is the only one any operation can reach.
  • The step note reports the returned value for pop and peek, so the difference between removing and looking is explicit.
  • The code panel follows the same trace, so the line return data[--size] is highlighted at the moment the plate leaves.

The cost of each operation

OperationWhat happensTime
push(v)Writes data[size] and increments sizeO(1)
pop()Decrements size and returns the old topO(1)
peek()Returns data[size - 1] without changing itO(1)

Every operation is constant time because nothing is ever shifted: the end of the array is the whole data structure.

The code that runs

class IntStack {
    private int[] data = new int[8];
    private int size = 0;

    void push(int v) {
        if (size == data.length) throw new IllegalStateException();  // full
        data[size++] = v;
    }

    int pop() {
        if (size == 0) throw new EmptyStackException();              // empty
        return data[--size];
    }

    int peek() {
        if (size == 0) throw new EmptyStackException();
        return data[size - 1];
    }
}

Both guard clauses are part of the trace, not decoration: an empty pop or a full push is the most common stack bug, and the scene shows the check running before the operation does.

Where a stack shows up next

Recursion is a stack the language keeps for you: every call frame is pushed and popped in the same order. Iterative depth-first search is the same structure written by hand, and the balanced-bracket and undo problems are one push and one pop each. Once this tower makes sense, all of those read the same way.
