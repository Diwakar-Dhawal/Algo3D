Queue visualiser in 3D

A queue has two ends and a rule about which one you use. Algo3D draws the slots in a row with head and tail pointing into it: values arrive at the rear, leave from the front, and the first value in is the first value out.

What the 3D view shows

  • A row of slots with the value in each one, and head / tail marked in the scene.
  • An enqueue slides a new tile in at the rear; a dequeue lifts the front tile out.
  • The shift is drawn, not hidden: on this array-backed queue, removing the front means every remaining value moves one slot left.
  • The step note names the value returned by dequeue and front, so removing and peeking stay distinct.
  • Click a slot to inspect it, and orbit the camera to see the row end-on.

The cost of each operation

OperationWhat happensTime
enqueue(v)Writes at tail and increments itO(1)
dequeue()Reads data[head], then shifts the rest leftO(n)
front()Reads data[head] and changes nothingO(1)

That O(n) dequeue is the point of the view. A circular buffer or a linked list removes the shift, and the difference is visible here as a cost you can literally watch move.

The code that runs

class IntQueue {
    private int[] data = new int[8];
    private int head = 0, tail = 0;

    void enqueue(int v) {
        if (tail == data.length) throw new IllegalStateException();  // full
        data[tail++] = v;
    }

    int dequeue() {
        if (head == tail) throw new NoSuchElementException();        // empty
        int v = data[head];
        for (int i = 1; i < tail; i++) data[i - 1] = data[i];        // shift
        tail--;
        return v;
    }

    int front() {
        return data[head];
    }
}

Where a queue shows up next

Breadth-first search is a queue with a graph inside it: the frontier is exactly “the things discovered but not yet visited”, which is first-in first-out by definition. Print queues, task schedulers and message buffers are the same shape, and the reason they are fair is the same reason BFS finds the shortest path in an unweighted graph.
