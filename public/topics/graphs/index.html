Graphs · BFS · DFS

Graph visualiser in 3D

A graph is the general case: any vertex can reach any other through an edge. Algo3D draws an undirected adjacency-list graph in space, marks the vertices already seen, and grows the frontier one step at a time — so the difference between breadth-first and depth-first is a shape you can point at rather than two code listings.

What the 3D view shows

  • Seven vertices, A to G, joined by nine undirected edges, floating in a force-style layout.
  • The frontier is visible at every step: the vertices discovered but not yet visited.
  • An edge lights up as it is traversed, and a vertex changes state when it is marked seen.
  • BFS spreads outward level by level through a queue; DFS dives along one path and backtracks through a stack.
  • Drag to orbit — in 3D the edges that cross on a flat drawing are visibly not touching.

The two traversals and their cost

TraversalData structureWhat it finds
BFSA queue of verticesShortest path in edge count, level by level
DFSA stack (or recursion)Reachability, and the basis for cycle detection and topological sort

Both run in O(V + E) with an adjacency list: every vertex is queued or pushed at most once, and every edge is looked at once from each end. The graph here has 7 vertices and 9 edges, so the whole traversal is 16 operations of work.

The code that runs

void bfs(Map<String, List<String>> g, String start) {
    Set<String> seen = new HashSet<>();
    Queue<String> q = new ArrayDeque<>();
    q.add(start);
    seen.add(start);
    while (!q.isEmpty()) {
        String u = q.poll();
        visit(u);
        for (String v : g.get(u)) {
            if (seen.add(v)) q.add(v);      // add returns false if already seen
        }
    }
}

The DFS program is the same loop with a Deque used as a stack, which is why the order of the visit changes completely while the code looks almost identical.

Why the third dimension helps

Graph drawings on paper are a compromise: edges are forced to cross, and a reader has to check whether two lines actually meet. In a 3D layout the positions are real, so an edge either joins two blocks or it does not. The frontier, the visited set and the traversed edges can also occupy different spaces without any of them hiding the others.
