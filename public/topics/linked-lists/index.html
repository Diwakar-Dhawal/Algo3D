Linked lists · nodes · next pointers

Linked list visualiser in 3D

An array puts its values next to each other in memory; a linked list does not. Algo3D draws the nodes as separate blocks joined by next pointers, so the part that actually makes a list work — the link you have to re-point — is the part you can see.

Run the linked-list view →

What the 3D view shows

  • One block per node, holding its value, with an edge to the next node and a clear end where null lives.
  • head is named, because losing it loses the list.
  • Inserting at the head creates a node and points it at the old head; inserting at the tail walks cur to the end first.
  • Deleting finds the node before the target and re-points its next, so the removed block leaves without anything shifting.
  • The traversal program moves cur along the chain one hop per step, which is the loop that every other list operation is built on.

The cost of each operation

OperationWhat happensTime
Insert at headNew node points at the old headO(1)
Insert at tailWalk to the last node, then linkO(n)
Delete by valueWalk to the node before it, then unlinkO(n)
Get the i-th valueFollow next i timesO(n) — no indexing

Compared with an array, that last row is the trade: reading a position becomes a walk, and inserting or removing a node becomes a pointer change instead of a shift.

The code that runs

class Node {
    int value;
    Node next;
    Node(int value) { this.value = value; }
}

Node insertHead(Node head, int v) {
    Node n = new Node(v);
    n.next = head;          // the old head hangs off the new node
    return n;
}

Node insertTail(Node head, int v) {
    Node n = new Node(v);
    if (head == null) return n;
    Node cur = head;
    while (cur.next != null) cur = cur.next;
    cur.next = n;
    return head;
}

Node delete(Node head, int v) {
    if (head == null) return null;
    if (head.value == v) return head.next;              // deleting the head
    Node cur = head;
    while (cur.next != null && cur.next.value != v) cur = cur.next;
    if (cur.next != null) cur.next = cur.next.next;     // unlink
    return head;
}

The two early returns in delete are the two cases people forget: an empty list, and the node you wanted being the head.

Why the picture matters here

Every linked-list bug is a pointer bug: a link that was overwritten before its value was used, a next that was never checked for null, or a node that is still reachable from nothing. In a console those bugs leave no trace at all. As blocks and edges, a lost chain is immediately visible, and so is the moment cur leaves the list.
