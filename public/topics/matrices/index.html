Matrices · traversal · transpose

Matrix visualiser in 3D

Two nested loops over a grid are easy to write and hard to picture. Algo3D lays the grid out as a plate of 3D cells with the row and column of each one printed on it, then walks the traversal you picked, marking every cell the moment it is read. The bounds top, bottom, left and right stay visible while they shrink, which is exactly the part of a spiral program that goes wrong.

What the 3D view shows

  • A grid of cells, each labelled m[row][col], standing on a themed plate instead of a flat table.
  • The cell being read lifts and turns gold; cells already collected stay marked so the trail of the walk is visible.
  • For the spiral, the four shrinking bounds are the story: the top row goes, then the right column, then the bottom row, then the left.
  • The step note counts what has been collected so far, so the output list is never a guess.
  • Drag to orbit and look along a row or a column, and the row-major order of the grid becomes obvious.

The two programs in the library

ProgramWhat it doesTime
SpiralReads the border, then the next border, until the grid is emptyO(rows × cols)
TransposeWrites m[r][c] into t[c][r] for every cellO(rows × cols), O(rows × cols) extra space

The code that runs

Spiral traversal, with the four bounds named the way the scene names them:

List<Integer> spiral(int[][] m) {
    List<Integer> out = new ArrayList<>();
    int top = 0, bottom = m.length - 1;
    int left = 0, right = m[0].length - 1;
    while (top <= bottom && left <= right) {
        for (int c = left; c <= right; c++) out.add(m[top][c]);
        top++;
        for (int r = top; r <= bottom; r++) out.add(m[r][right]);
        right--;
        for (int c = right; c >= left && top <= bottom; c--) out.add(m[bottom][c]);
        bottom--;
        for (int r = bottom; r >= top && left <= right; r--) out.add(m[r][left]);
        left++;
    }
    return out;
}

The transpose program allocates int[cols][rows] and copies one cell per iteration, so the scene shows a cell landing in the mirrored position of a second grid.

Why draw the grid in three dimensions

On a whiteboard a grid is already two-dimensional, so the third dimension buys something different: depth. Cells that have been read sit a little differently from cells that have not, the bounds can be drawn as edges in the air, and the order of the walk is visible from an angle rather than inferred from numbers in a console.

That matters most for the spiral, where a single missing bound check turns an elegant traversal into a duplicated cell — the scene shows the extra read the moment it happens.
